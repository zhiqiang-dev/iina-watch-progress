# 保存与列表性能说明（0.1.4）

## 0.1.4 搜索与局部刷新

2026-11-26：本版延续 0.1.3 的双快照存储与采样频率，减少搜索、浏览偏好和界面的重复工作。

- 搜索去抖 150 ms，输入法 composition 期间停止查询，Enter 可立即应用；切换目录取消旧查询并重置输入法调度状态。
- 为当前排序保留整目录 ID 顺序，改变关键词/状态筛选时仅过滤。文件名或当前排序键更新时使缓存失效，避免隐藏项目变化后恢复搜索得到旧顺序。
- 连续滚轮只在首次改变跟随状态时更新导航；浏览状态与保存值完全相同时跳过 localStorage 写入。
- 统计、继续观看、存储、选中详情、导航和空状态分别比较依赖。内容相同的桥接记录保留原模型引用；分辨率/编码相同时复用缓存对象。
- 只更新存储提示时不安排虚拟列表绘制。记录在视口外、选中/播放标记未变、排序未变时也不安排可见行绘制；滚动或排序变化时仍正常安排。
- 预览基准模式增加 `data-render-stats`、`data-render-continue`、`data-render-storage`、`data-render-selection`、`data-render-navigation`、`data-render-list-state` 区域计数。生产插件不输出这些 DOM 指标。

复现本次基准（Git 克隆中需有 `v0.1.3` 标签）：

```sh
pnpm benchmark:queries --output docs/performance-results-0.1.4.json
pnpm exec vitest run tests/sidebar.test.ts tests/search-input.test.ts tests/video-list-model.test.ts
```

基准以 `git show v0.1.3:src/ui/video-list-model.ts` 编译的真实旧算法为对照，100 个查询依次使用空、宽和窄关键词。两版查询结果逐项比较一致，再分别预热两次，取 7 次运行的中位数。定时不含 UI、输入去抖等待或播放器通信。见 [原始结果](performance-results-0.1.4.json)。

| 合成记录数 | 100 次查询，0.1.3 → 0.1.4 | 完整排序次数（含初次载入） | 当前快照临时文件保存及读回 |
| --- | ---: | ---: | ---: |
| 1000 | 16.063 → 6.529 ms | 100 → 1 | 1.311 ms，332,153 字节 |
| 10000 | 194.008 → 86.790 ms | 100 → 1 | 14.363 ms，3,320,153 字节 |

临时文件测量包含序列化、同步写文件与读回，路径由 mkdtemp 隔离，结束删除，不读取真实观看记录；受操作系统缓存影响，未 fsync，不能据此判断 SSD 物理写入、断电持久性或 IINA 保存延迟。本版未修改观看记录存储算法，不能将这组数据描述为磁盘写入量下降。

109 项自动测试通过。其中 DOM 集成测试运行实际编译的侧栏脚本与真实 HTML，验证长列表挂载数量、输入法、立即查询、保存状态更新不绘制视频行、屏幕外位置变化不绘制可见行、重复滚轮不刷新导航，以及完成/只读状态、编号筛选恢复、最近目录和拖动取消。DOM 环境的视口高度为测试输入，不计算真实布局；结果不代表 WKWebView 帧率。

本次界面控制工具连续超时，未完成 0.1.4 新外观、快捷键宿主行为、滚动、CPU 或耗电实机验证，也没有新截图。0.1.3 的实机结果仅作为历史记录。后续应在隔离合成课程目录、相同窗口尺寸和播放设置下，分别运行两版，每个场景至少重复 3 次：暂停静置 30 秒、播放 30 秒、连续滚动 10 秒、搜索与筛选各 10 次；同时观察 IINA 和关联 WebContent 进程的 CPU 与内存，并记录保存耗时和滚动帧时间。在这些数据完成前不声称真实 IINA 提速比例。

日期：2026-11-25。目标是减少持续播放和长列表浏览时的重复工作，保留本地持久化、双快照恢复以及已完成状态不回退的语义。

## 0.1.3 新增优化

- 播放周期读取 `path` 和 `time-pos`，时长、暂停、倍速、跳转和缓冲状态在加载及对应属性事件时更新缓存。测试确认暂停后周期任务不再读取 mpv 属性；窗口状态检查仍独立运行。
- 列表增加 ID 到排序位置的索引。进度/最近观看变化后，先比较相邻项；顺序未改变时不删除和插入数组。只有真正移动时才更新受影响位置的索引。关键词和标准化文件名缓存，避免每次采样重复拆词/转换大小写。
- 排序改变时以视口顶端的文件 ID 和行内偏移恢复滚动位置，避免活动项移动使正在浏览的内容跳动。拖动中的行保留到交互结束，降低被增量重绘打断的可能。
- WebView 报告隐藏时停止绘制并合并待发记录；恢复后使用最新状态。主脚本也处理可见性通知、明确显示其他面板及播放器最小化，减少隐藏界面的消息。
- IINA 1.5.1 的 `core.window.sidebar` 对可见插件侧栏也会返回空值。因此空值按“未知”处理，继续允许更新，防止可见列表停留在旧画面。该兼容策略优先保证正确性，不能承诺所有隐藏情形都完全停止 UI 工作。依据：[IINA 1.5.1 实现](https://github.com/iina/iina/blob/v1.5.1/iina/JavascriptAPICore.swift#L235)。
- 自动进入已完成状态立即落盘；普通位置仍按用户选择的间隔合并保存。折叠的视频详情不持续格式化时间和更新详情文本；分辨率与编码仅加载时读取，界面最多缓存 100 项。

这些改动没有降低实际观看时长采样频率，也没有把每秒内存更新改为每秒写盘。两份快照和数据 schema 保持兼容。

## 每秒更新是否意味着每秒写盘

不是。播放器每秒采样到内存，通过消息把变化交给界面；全局存储只在有变化时按保存间隔写入。默认仍为 5 秒，可在「设置与数据 → 自动保存间隔」选 15、30、60 秒。暂停、切换、结束、关闭窗口和手动操作立即尝试保存。暂停且数据未变化、重复选择现有设置、重复标记已完成，都不会再次写盘。

每个保存周期只写 `records.json` 或 `records.backup.json` 中的一份，写后读回比较成功才认定保存完成。另一个槽位保留上一份已验证快照；启动时仍严格解析、校验版本及全部记录，选择最新有效 revision。格式仍为 schemaVersion 1，旧版缺少保存间隔时使用 5 秒，加载本身不触发重写。

以单份约 137,309 字节的快照估算，持续播放一小时、忽略即时保存：

| 自动保存间隔 | 周期写入次数/小时 | JSON 逻辑写入量/小时 |
| --- | ---: | ---: |
| 5 秒 | 约 720 | 约 98.9 MB |
| 15 秒 | 约 240 | 约 33.0 MB |
| 30 秒 | 约 120 | 约 16.5 MB |
| 60 秒 | 约 60 | 约 8.2 MB |

MB 按十进制计算。读回还会产生相应的逻辑读取；操作系统缓存、文件系统与 SSD 控制器会影响实际物理 I/O，表格不能用于推算 SSD 的真实写入量。记录数量增加会使完整快照变大。延长间隔能直接减少周期写入，但异常退出也可能丢失最近约一个周期的更新，损坏最新快照时备用槽位还可能再落后一个周期。

## 具体改动

| 环节 | 原先的重复工作 | 0.1.2 行为 |
| --- | --- | --- |
| 播放消息 | 更新一条记录也发送整个订阅列表 | 初次订阅发送完整快照，之后只发送变化记录；保存状态更新可发送零条记录 |
| 异步消息 | 待发的全量状态合并 | 以文件 ID 合并补丁，保留初始快照，按目录范围丢弃过期响应 |
| 列表计算 | 进度更新重做筛选、排序与统计 | Map 查找、增量计数；必要时对变化项二分插入，文件名排序下普通进度更新不重新排序 |
| 可见行 | 滚动或更新重新创建整段可见 DOM | 按文件 ID 复用行，只增删进出视口的行；每帧至多渲染一次，未变的显示内容跳过修改 |
| 文件夹扫描 | 同目录的短时间重复事件再次读目录 | 缓存最近一个目录 5 秒；用户点刷新强制读取 |
| 播放采样 | 暂停时继续读属性、重复发相同位置 | 暂停停止周期采样；位置、时长等事件仍捕捉暂停拖动和状态变化 |
| 保存计算 | 两次完整序列化、两次解析及逐条校验 | 一次序列化生成相同校验格式，写后逐字比较读回内容；启动时完整校验保留 |

当前依然会定期写入整个 JSON，没有宣称“单条更新只写单条磁盘记录”。本次未引入数据库、追加日志或视频内容指纹。目录里新增/删除文件，在缓存期内可能暂不显示，点击刷新即可立即更新。进度/最近观看排序需要移动变化项时，数组插入仍可能有 O(n) 的移动成本。

## 可复现基准

```sh
pnpm benchmark
# 重新生成结果文件：
pnpm benchmark --output docs/performance-results.json

pnpm build
pnpm preview
# 打开 http://127.0.0.1:4173/?count=1000&benchmark=1&live=1
```

脚本在 Node.js v22.22.3 / darwin arm64 上，以 1000、10000 条合成记录运行；预热后取 7 次的中位数。前值复现 0.1.1 保存/列表算法，后值运行被测版本核心实现；文件端口使用内存 Map。消息大小测量记录消息，不含播放器到 WebView 的其他元数据。下面保留 [0.1.2 原始结果](performance-results.json)，用于历史对照。

| 合成记录数 | 全量记录消息 → 单条补丁 | 单次快照处理，前 → 后 | 100 次列表更新计算，前 → 后 |
| --- | ---: | ---: | ---: |
| 1000 | 299,807 → 447 字节 | 4.999 → 0.691 ms | 25.169 → 0.060 ms |
| 10000 | 3,026,810 → 447 字节 | 56.662 → 7.676 ms | 267.913 → 0.083 ms |

基准使用不含新保存间隔字段的兼容设置，默认设置下消息会多出少量字节；字节数与文件名长度等有关。列表时间不含 DOM、浏览器布局和绘制；保存时间不含真实磁盘。上述比值不能视为整个 IINA 的加速比例，也不能据此推断滚动帧率。

0.1.2 浏览器交互验证在 400×820 下使用 1000 条记录，首尾视口均只挂载 8 行；正常文件名排序下完整排序计数保持为 1，播放更新未重新创建已有可见行。仅预览且 URL 含 `benchmark=1` 时，`#list` 的 `data-created`、`data-patched`、`data-frames`、`data-sorts` 提供计数；生产插件不输出这些 DOM 指标。它们用于检查工作量，不能替代 WKWebView 的帧时间测量。

0.1.3 结果见 [新增基准](performance-results-0.1.3.json)：

| 合成记录数 | 单次快照处理，原算法 → 当前 | 100 次文件名排序更新，原算法 → 当前 | 100 次最近观看更新 | 最近观看数组移动 |
| --- | ---: | ---: | ---: | ---: |
| 1000 | 5.344 → 0.745 ms | 25.859 → 0.064 ms | 0.056 ms | 0 |
| 10000 | 57.749 → 8.963 ms | 275.890 → 0.081 ms | 0.060 ms | 0 |

最近观看用例持续更新已经排在首位的同一个视频，0 次移动是该用例的结果，不代表所有更新都无需移动。当前脚本运行结果会随负载变化。浏览器 400×820 下，10000 条舒适列表跳到末尾仅挂载 7 行，再定位当前项无需创建一万行；最近观看播放更新期间 `data-moves` 保持 0。搜索/筛选/排序操作会增加完整排序计数，普通播放更新不增加。0.1.3 额外提供 `data-moves`，仍仅在预览基准模式启用。

浏览偏好写入与视频记录保存分开：最多 40 个文件夹，以 600 ms 去抖保存到 WebView 本地存储，不将滚动事件写入观看 JSON。虚拟列表舒适/紧凑行高分别为 88/68 px，密度改变保持浏览锚点。

## 验证边界

92 项测试通过，包括损坏/中断恢复、旧记录兼容、多窗口合并、重置防回写、增量排序和位置索引参考对照、隐藏消息合并、属性缓存、保存间隔、暂停/完成立即保存、侧栏空值兼容和播放器复用。已在本机 IINA 1.5.1 验证播放/暂停、拖动跳转、自动下一项、侧栏实时更新和关闭后重开。151 条记录身份无缺失、最远位置无减少、完成状态无撤销；两个合成测试记录有正常变化，其余 149 条课程记录完全一致。

尚未测量真实长时间 CPU、耗电、磁盘延迟或 10000 条记录在实际 WKWebView 中的滚动帧率。旧备份不可用于覆盖正常观看产生的新进度。正式稳定版仍需完成 [验收记录](acceptance.md) 中未完成的真实播放器场景。
